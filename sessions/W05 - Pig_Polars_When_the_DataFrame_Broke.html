Foundation terms

Three words you'll need tonight

They sound technical, but each one names something Priya already does in pandas.

Rows & columns

A row is one record — one order. A column is one attribute of every record (Region, OrderValue).

orders.shape
# (n_rows, n_columns)

Tuple

The formal word for "one row." Pig and databases call a row a tuple — an ordered set of field values.

(1, 'West', 500)
# one tuple

Predicate

The condition you test each row against to decide whether to keep it — what goes inside a filter.

OrderValue > 1000
# true / false per row
Put together: FILTER orders BY OrderValue > 1000 = keep every tuple where the predicate is true.
Meet the tools

Two DataFrames for two different walls

Same three moves — filter, group, aggregate — expressed at a different scale.

Pig

"My DataFrame doesn't fit on one machine."
  • A scripting language, Pig Latin, for describing table transformations.
  • Runs the same filter / group / aggregate ideas across a Hadoop cluster.
  • Never loads the whole table into memory — the cluster reads it in pieces.

Polars

"My DataFrame is too slow on one machine."
  • A Python DataFrame library — syntax feels close to pandas.
  • A Rust engine underneath: multi-threaded, and it plans before it runs.
  • Still one machine, but built to use every core of it well.

Lazy execution

What does "lazy" actually mean?

Write the recipe
→
Keep it on paper
→
Optimize the steps
→
Cook only when
someone orders
  • A pandas DataFrame is eager: every line executes the moment you write it.
  • Lazy systems build a plan, check what output is actually needed, then run the plan at the end.
  • That delay enables optimization: read fewer columns, apply filters earlier, merge steps.
  • Execution starts only when someone asks to view or save the final result.
Same idea, two languages

Lazy execution: Pig vs. Polars

pandas (eager): big = orders[orders['OrderValue'] > 1000]  ← runs the instant you write it
Pig 
orders = LOAD 'orders.csv'
  USING PigStorage(',');
large  = FILTER orders BY
  OrderValue > 1000;
by_reg = GROUP large BY Region;
summary = FOREACH by_reg GENERATE
  group, COUNT(large);
-- no job has run yet
DUMP summary;  -- now it executes
Polars 
import polars as pl

summary = (
  pl.scan_csv('orders.csv')
    .filter(pl.col('OrderValue')>1000)
    .group_by('Region')
    .agg(pl.len().alias('Orders'))
)
# nothing materialized yet
print(summary.collect())  # executes
Comparison

Eager vs. lazy: the key difference

pandas DataFrame — eager

  • Each operation produces a real result immediately.
  • Easy mental model: one line runs, output exists right away.
  • Great for small demos and interactive exploration.
  • Wastes work if later steps discard rows or columns you already loaded.

Pig / Polars — lazy

  • Each operation just adds a step to a plan — nothing runs yet.
  • The optimizer can rearrange or simplify the plan before execution.
  • Built for large files and multi-step pipelines.
  • A final action triggers it: DUMP, STORE, .collect().

The morning after · 9:15 AM
Stand-up · Meera has one question before the leadership review
"Which region had the highest sales last night, ignoring the tiny ₹500 orders?"

One business question. The team now has three ways to answer it — and the next two slides show the exact same logic in Pig (for the full 40 GB on the cluster) and Polars (for a fast local slice). Watch how little actually changes.

Full example · the cluster answer

QuickKart regional sales — the Pig script

orders = LOAD 'quickkart_orders.csv' USING PigStorage(',')
  AS (OrderID:int, Region:chararray, Category:chararray, OrderValue:double);

valid     = FILTER orders BY OrderValue > 500;
by_region = GROUP valid BY Region;

summary = FOREACH by_region GENERATE
  group AS Region,
  COUNT(valid)          AS NumberOfOrders,
  SUM(valid.OrderValue) AS TotalSales,
  AVG(valid.OrderValue) AS AverageOrderValue;

sorted = ORDER summary BY TotalSales DESC;
STORE sorted INTO 'output/regional_summary' USING PigStorage(',');
Full example · the fast local answer

Same question — the Polars version

Identical logic, one machine, results in seconds — and it reads like the pandas Priya already knows.

import polars as pl

summary = (
    pl.scan_csv('quickkart_orders.csv')
      .filter(pl.col('OrderValue') > 500)
      .group_by('Region')
      .agg(
          pl.len().alias('NumberOfOrders'),
          pl.col('OrderValue').sum().alias('TotalSales'),
          pl.col('OrderValue').mean().round(2).alias('AverageOrderValue')
      )
      .sort('TotalSales', descending=True)
)
print(summary.collect())

Diagnostic operators — checking your work

No pandas or Polars equivalent — these are Grunt-shell tools for inspecting a relation before you trust it.

DUMP

Print the contents of a relation to the console.

dump summary;

DESCRIBE

Show the schema — field names and types.

describe orders;

EXPLAIN

View the logical, physical, or MapReduce plan.

explain summary;

ILLUSTRATE

Step through a script on a small sample — best for debugging.

illustrate summary;
Classroom habitAfter every GROUP or JOIN, run DESCRIBE before FOREACH — it catches schema surprises before they become wrong numbers.

Run modes & engines

Local mode (pig -x local) — one JVM, local filesystem, for development.

MapReduce mode (default) — runs on the Hadoop cluster, reads/writes HDFS.

Three engines: MapReduce, Tez, Spark. On Tez/Spark, Pig builds a DAG — same script, better performance.

Important limits

What Polars does not simulate

No HDFS block replication

No DataNode / NameNode failures

No distributed MapReduce jobs

No cluster scheduling delays

  • Polars is excellent for teaching DataFrame syntax and lazy planning — it is not a Hadoop cluster.
  • It can't teach fault tolerance, because it never runs on more than one machine.
  • Use diagrams or small file/folder simulations to teach HDFS replication and MapReduce stages.
  • Then move students to Spark / Databricks when they're ready for real distributed execution.

Two escape hatches.

When the DataFrame breaks because it's too big, reach for Pig and the cluster. When it breaks because it's too slow, reach for Polars and a smarter engine. The pandas thinking never changes — only the scale does.
