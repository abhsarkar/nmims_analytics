Feature Engineering

Raw logs are noise. Features are signal.

A model can't understand "User_42 played an Arijit song at 11pm on mobile for 142 seconds." It needs columns with numbers.
❌ RAW EVENT LOG
user_42 | song_187 | 23:14:07
action: play | device: mobile
duration: 142s | song_len: 224s
genre: Bollywood | artist: Arijit
playlist: "Late Night Vibes" pos: 3
prev_action: skipped song_186
→
✅ ENGINEERED FEATURES
completion_rate = 0.634
hour_sin = -0.966
hour_cos = 0.259
is_mobile = 1
artist_affinity = 0.82
prev_skip = 1
Feature engineering is the bridge between the app and the model. This is where 80% of the business value lives — not in the algorithm.
Feature Engineering — The Recipes

Six patterns that work everywhere — not just music.

RECIPE 1

Ratios

completion_rate = played / duration
The most powerful trick. Normalizes across different song lengths. 0.1 = bailed. 1.0 = full listen.

RECIPE 2

Cyclical Encoding

hour_sin = sin(2π × hour/24)
Hour 23 is close to hour 0, but numerically far. Sin/cos fix this. Works for day-of-week, month, season.

RECIPE 3

Binning

time_of_day = "Late Night"
Convert continuous numbers to business categories. Hour 23 → "Night". Release 3 days ago → "This Week".

RECIPE 4

Recency

is_new_release = (days_ago ≤ 30)
New songs behave differently. Flag them. Bin release age into buckets: Week, Month, Quarter, Catalog.

RECIPE 5

Interactions

affinity × completion
Feature × Feature. High affinity + high completion = superfan. This combo predicts better than either alone.

RECIPE 6

Boolean Flags

is_premium = 1, is_weekend = 0
Business logic as features. Premium users skip less. Weekend sessions are longer. Encode the domain knowledge.

Feature Engineering — Encoding

How do you turn "Bollywood" into a number?

Models need numbers. But encoding wrong creates fake relationships. "Bollywood = 1, EDM = 5" implies EDM > Bollywood. That's a lie.
Label Encoding
Bollywood → 0
Classical → 1
EDM → 2
Pop → 3
✓ Use with: Decision Trees, Random Forest, XGBoost (they split, don't compare magnitude)
One-Hot Encoding
genre_bollywood → 1 0 0 0
genre_classical → 0 1 0 0
genre_edm → 0 0 1 0
genre_pop → 0 0 0 1
✓ Use with: Linear/Logistic Regression, Neural Nets, SVM (no fake ordering)
Ordinal Encoding
Low → 1
Medium → 2
High → 3
✓ Use when: There IS a natural order (education level, rating stars, subscription tier)
Wrong encoding = lying to your model. The model trusts you. Don't make EDM > Bollywood.
Feature Engineering — Scaling

Tempo = 128, Followers = 500,000. Same scale?

Distance-based models (KNN, K-Means, SVM) and gradient-based models (Linear Regression, Neural Nets) are dominated by the biggest number. If followers is 500K and tempo is 128, the model thinks only followers matter.
❌ Unscaled
tempo: 50 – 180
followers: 1 – 500,000
position: 1 – 50
Followers drowns everything
✅ StandardScaler
mean = 0, std = 1
All features centered
Most common choice
Use for regression, SVM, PCA
✅ MinMaxScaler
range [0, 1]
Preserves shape
Good for neural nets
Use for NN, image pixels
⚠️ When NOT to scale:
Decision Trees, Random Forest, XGBoost — these split on thresholds, not distances. Scaling has zero effect. Save the compute.
Feature Engineering — Make or Break

Good features make dumb models smart.
Bad features make smart models dumb.

❌ Weak Features
• Wrong time zone — 2pm IST ≠ 2pm EST
• Bot plays counted as real listens
• New artist with no history → cold start
• Regional language signal missing entirely
• Festival context (Navratri, Diwali) ignored
• Raw user_id as a feature (memorization!)
✅ Strong Features
• Clean events with deduplication
• Time-window aggregations (last 7d, 30d, 90d)
• Cold-start fallbacks (genre avg, popularity)
• Language & region signals
• Seasonality / festival flags
• Interaction features (affinity × completion)
Feature engineering encodes domain understanding. An algorithm can find patterns — but only in the features you give it. Garbage in, garbage out. Intelligence in, magic out.
Classification

The model answers: which bucket?

Every time Saavn decides "show this ad" or "don't show this ad," "this user will churn" or "this user will stay" — that's classification. The output is always a category, not a number.
BINARY

Skip or Not Skip?

Two classes. Yes/No. Will the user skip this song in the first 30 seconds? Output: Skip (68%) / Not Skip (32%).

MULTI-CLASS

What Mood?

Multiple classes. Chill / Party / Workout / Focus / Romance. The model picks one. Same math, more buckets.

MULTI-LABEL

Which Playlists?

A song can belong to multiple playlists simultaneously. Chill AND Study AND Sleep. Multiple labels at once.

If the answer is a label, a category, a yes/no, or a bucket — it's classification.
Classification — Decision Boundary

The model draws an invisible line through your data.

Imagine plotting every user on two axes: tempo preference (x) and evening listening hours (y). Skip users cluster in one region. Non-skip users in another. Classification finds the line that separates them.
What's happening:
● Red dots = users who skipped
● Green dots = users who listened
— Gold line = the decision boundary
A new user lands on one side → the model predicts their class.
The line isn't always straight. Trees, forests, and neural networks draw complex, curvy boundaries — but the idea is the same.

Classification — The Tradeoff

Precision vs Recall — the business decision hiding inside the math.

High Precision: "When I say skip, I'm sure."
The model only flags a song as "skip" when it's very confident. Fewer false alarms — but it misses some real skips. Users hear a few bad songs, but every recommendation it blocks was truly bad.
→ Use when: cost of wrong flag is high
→ Music: ad targeting (don't waste ₹ on wrong audience)
→ Real world: spam filter (don't eat good emails)
High Recall: "I catch every skip, even if I'm sometimes wrong."
The model flags anything that might be a skip. It catches almost all bad recommendations — but also blocks some songs the user would have liked. Overprotective, but safe.
→ Use when: cost of missing a case is high
→ Music: churn prediction (don't miss a user about to leave)
→ Real world: cancer screening (don't miss a tumor)
There is no "correct" answer. Precision vs Recall is a business decision disguised as a math problem. The model gives you a dial — the business decides where to set it.
Classification — Algorithm Menu

Same question, different tools. Pick by context.

SIMPLE

Logistic Regression

Draws a straight line. Fast, interpretable. Start here. "Is this user premium or free?"

INTERPRETABLE

Decision Tree

If tempo > 120 AND hour > 22 → Workout. Rules a human can read. Easy to explain to business.

POWERFUL

Random Forest

100 trees vote together. Robust, hard to break. The industry default for tabular data.

COMPETITION

XGBoost

Trees that learn from each other's mistakes. Wins Kaggle. Powers Spotify Discover Weekly.

DEEP

Neural Network

Learns complex patterns from raw audio, text, images. Overkill for tabular, essential for audio features.

BASELINE

Naive Bayes

Assumes features are independent. Surprisingly good for text classification — genre from lyrics.

GEOMETRIC

SVM

Finds the widest possible gap between classes. Works well in high-dimensional feature spaces.

LAZY

KNN

No training. Just: "find the 5 most similar users and copy their answer." Simple but slow at scale.

Regression

The model answers: how much?

Every time Spotify predicts "this song will get 1.2 million streams" or "this user will listen for 47 minutes today" — that's regression. The output is always a continuous number.
STREAMS

How many plays tomorrow?

Predict stream count for a new release. Decides playlist placement, marketing spend, royalty estimates.

TIME

How long will they listen?

Predict session duration in minutes. Drives ad insertion timing: more minutes = more ad slots = more revenue.

REVENUE

What's a user worth?

Customer lifetime value (CLV). How much revenue will this user generate over the next 12 months? ₹0 to ₹12,000.

If the answer is a number on a continuous scale — streams, minutes, rupees, probability — it's regression.

Regression — The Scoreboard

How wrong are we? MAE, RMSE, R²

MAE
Mean Absolute Error
"On average, we're off by 15,000 streams." Simple. Intuitive. Every error counts equally.
= average( |actual - predicted| )
RMSE
Root Mean Squared Error
"We penalize big misses more." A prediction off by 100K hurts way more than ten predictions off by 10K.
= √(average( (actual - predicted)² ))
R²
R-Squared
"Our model explains 78% of why streams vary." 1.0 = perfect. 0 = useless. Can go negative if you're worse than guessing the mean.
= 1 - (SS_res / SS_tot)
Business translation: "If MAE = 15K streams and we pay ₹0.004 per stream in royalties, every wrong prediction costs us ₹60 per song per day."
Regression — The Trap

Overfitting — the model that memorized the textbook but can't pass the exam.

Underfitting
📏
Too simple. A straight line through curved data. Misses patterns. "All songs get 50K streams."
Train: bad · Test: bad
Just Right ✓
🎯
Captures the real pattern. Generalizes to new songs it hasn't seen. This is the goal.
Train: good · Test: good
Overfitting
🐍
Memorizes every training song perfectly. Wiggles through every dot. Fails completely on new data.
Train: perfect · Test: terrible
MBA analogy: Overfitting is studying only last year's exam paper. You ace the mock. You bomb the real thing. The model needs to learn the subject, not the exam.
Regression — Algorithm Menu

Same question, different tools.

START HERE

Linear Regression

y = mx + b. The straight line. Fast, interpretable, surprisingly competitive. Always try first.

REGULARIZED

Ridge / Lasso

Linear regression + penalty for complexity. Lasso kills useless features automatically. Ridge keeps all, shrinks them.

NON-LINEAR

Decision Tree Regressor

Splits data into boxes. Each box predicts one number. Can capture "if genre=Bollywood AND Friday → 2x streams."

INDUSTRY STANDARD

XGBoost / LightGBM

Gradient-boosted trees. The default for production tabular regression. Spotify, Netflix, Uber all use this.

Clustering

The model answers: who belongs together?

No labels. No "right answer." You hand the algorithm user behavior data and it finds natural groups on its own. This is unsupervised learning — the model discovers structure nobody told it about.
LISTENER TRIBES

Who Are Our Users?

Late-night lo-fi listeners. Gym-playlist power users. Devotional morning streamers. The algorithm finds them — humans name them.

SONG GROUPS

Which Songs Go Together?

Group songs by audio features (tempo, energy, valence). Auto-generate playlists that feel coherent to humans.

ANOMALIES

Who Doesn't Belong?

Spot bots. Fake streams. Listeners with impossible patterns. "This account played 800 songs in one hour." Doesn't cluster with anyone.

If there's no target column, no label, no "right answer" — and you want to find natural groups — it's clustering.

Clustering — The Hard Question

How many clusters? The Elbow Method.

K-Means needs you to choose K upfront. Too few = everything lumped together. Too many = meaningless micro-segments. The elbow chart helps you find the sweet spot.
Reading the Elbow:
Y-axis: Within-cluster sum of squares (WCSS) — how "tight" the clusters are.
X-axis: Number of clusters (K).
The curve drops fast, then flattens. The bend = the elbow = your sweet spot.
Here, K = 4 is the elbow. Going to K=5 or 6 barely improves tightness but adds complexity.
But always validate with business sense. If marketing can only run 3 campaigns, K=3 might be better even if the math says 4.
Clustering — Algorithm Menu

Different algorithms find different shapes.

DEFAULT

K-Means

Fast, scalable. Finds circular blobs. You choose K. Start here. Works for most business segmentation.

HIERARCHICAL

Agglomerative

Bottom-up: each user starts alone, pairs merge. Creates a tree (dendrogram). Cut at any level to get K clusters.

DENSITY

DBSCAN

Finds clusters of any shape. Also finds outliers (noise points). Great for fraud/bot detection. No need to choose K.

PROBABILISTIC

GMM

Gaussian Mixture Models. Each point has a probability of belonging to each cluster. "70% Chill, 30% Workout."

K-Means for speed and simplicity. DBSCAN when you don't know K. GMM when users belong to multiple tribes. Choose by the business question, not the math.
