Before you open it · the "Don't Panic" guide

What on earth
is Databricks?

You've never seen it. You've never used it. You may have heard the name and immediately felt stressed. This page exists so that by the time you actually open Databricks, nothing surprises you.

You are not here to become an engineer.

You will not memorise commands. You will not install anything. You will not break anything. Databricks is free (Community Edition), runs in your browser, and the worst thing that can happen is you see an error message — which you'll just delete and try again.

Step 1 · What even is this thing?

Start here: the race car and the engine

Forget the website. Forget the logo. There are only two things to understand.

🏎️
Spark is the engine.

Spark is a very fast engine for processing huge amounts of data. Think of it as the engine inside a Formula 1 car — incredibly powerful, but you wouldn't buy a bare engine and try to drive it down the road. You need a car around it.

🏁
Databricks is the race car built around that engine.

Databricks wraps Spark in a friendly car — with a dashboard, a steering wheel, a seat, and buttons you can actually press. Engine included, ready to drive. You don't install Spark. You don't configure Spark. You open a browser, log in, and the engine is already running.

Why this matters to youWhen someone says "we use Spark," they mean the engine. When they say "we use Databricks," they mean the whole car. In class, you're driving the car. You don't need to understand the engine's internals any more than you need to understand combustion to drive a Honda.

What it replaces

Excel, but for huge data

When your CSV is 40 GB and Excel crashes or freezes, Databricks handles it without blinking. Same verbs — filter, group, total, sort — just on a much bigger desk.

Who uses it

Everyone large

Shell, Flipkart, HDFC, Grab, thousands of companies. If an Indian enterprise says "data platform," there's a good chance Databricks is underneath.

What it costs you

₹0

Community Edition is free. No credit card, no trial expiry. It's Databricks' way of letting students and small teams try the car without buying it.

Step 3 · Notebooks

The end of "email me the output"

A notebook is just a document where you can write text AND run code, and see the result right there. Think Google Docs meets a calculator.

📓
A notebook is a page with boxes.

Each box is called a cell. A cell can contain a note (text) or a small piece of code. You press ▶ on a code cell and the result appears directly below it — no separate window, no email, no export. The answer is right there.

What if it breaks?

Red text = just try again

An error message appears in red. It's not you — it's usually a typo or a file that hasn't been uploaded yet. Nothing is destroyed. Fix or re-run.

With notebooks: the code, the output, the notes, and the charts are all in one living document. Meera opens the same notebook and sees everything. End of email chains.
Step 4 · Compute

The kitchen is already built — just walk in

This is the part every tutorial gets wrong. Older versions of Databricks made you "create a cluster" before you could run anything. The Free Edition doesn't. It uses something called serverless compute — the kitchen is already running. You just start cooking.

🍳
In old Databricks: you had to build the kitchen before cooking.

Tutorials, YouTube videos, and even some textbooks will tell you to "create a cluster." That was the old way — like renting a kitchen, turning on the gas, waiting 5 minutes. The Free Edition skips all of that. The kitchen (compute) is already there. When you open a notebook and press ▶, it just runs.

Clusters — manual setup

If a tutorial says "create a cluster"Ignore it. That tutorial was written for the old Community Edition or for paid Databricks. In your Free Edition, compute is serverless — it's already there. If something doesn't run, it's not a cluster problem — it's more likely a typo in the code or a file that hasn't been uploaded yet.

None of that applies to you. The Free Edition removed the hardest step. All you do is: open notebook → press ▶ → read the result.
Step 5 · Storage (DBFS)

The universal phone charger

You need to put your data file somewhere Databricks can see it. That somewhere is called DBFS.

🔌
DBFS = one plug that works everywhere.

In real companies, data sits on Amazon (AWS), Microsoft (Azure), or Google (GCP). DBFS is a universal adapter — you write one file path, and it works no matter which cloud the company uses. You never think about the cloud.

For us? It's even simpler: drag a CSV file into the upload box, and it lands in DBFS. You'll refer to it as /FileStore/your_file.csv.

How you upload

Drag and drop

Click "Data" in the sidebar → "Add data" → drag your CSV. Done. The file is now at /FileStore/...

How you read it

One line of code

spark.read.csv("/FileStore/file.csv") — that's it. Already in the notebook for you.

How big can it be?

Way bigger than Excel

Excel dies at a few hundred MB. Databricks handles gigabytes to terabytes without sweating.

Step 6 · What you actually do in the lab

The same four verbs — on a bigger desk

You already know how to do this. You've done it in Excel. You've done it in SQL. You've done it in Hive. The verbs never change — only where they run.

🔍

Filter

Keep only the rows you care about

📁

Group

Put rows into buckets (by region, by hour…)

➕

Total

Count, sum, or average each bucket

↕️

Sort

Rank by biggest, newest, most popular

Here's what that looks like in a notebook — with the English translation first:

QuickKart_Lab.py — "Top pages with errors"
📖 Read this — the English version
"From all 200,000 log entries, filter to only server errors (status 500), group by page URL, count how many errors each page had, and sort so the worst page is on top."
Python✓ ran in 1.8s
errors = df.filter(df.status == "500") # filter
    .groupBy("url")                # group
    .count()                    # total
    .orderBy("count", ascending=False) # sort

display(errors)
